## 5. New findings (diagnosed and recorded; not fixed, no rerun)

### N3. An unrequested "Worth knowing" item is shown without any materiality check (confirmed)

The reply wrote a WORTH_KNOWING block about Columbus Circle, against the prompt's rule to include unrequested information only when it materially changes the answer. `AnswerComposer` shows WORTH_KNOWING for any ask as long as its claims are current, so the model's judgment of materiality is accepted as-is.

The same side claim appeared in run 1. It is model behaviour that the engine does not constrain.

**Proposed general fix:** a WORTH_KNOWING item must say what it changes (for example `changes=<the decision, cost or safety point it affects>`). An item that names nothing it changes, or that rests only on claims not load-bearing for the objective, would not be shown.

### N4. A sentence can state more than the claim and evidence it cites (confirmed, general)

The status qualifier judges each sentence by its claims' **statuses**. It does not check that the sentence's content stays within those claims and their cited text. So "where Massachusetts Avenue NE meets First Street NE" went out unqualified under an established claim whose evidence does not contain it.

**Proposed direction:** a conservative deterministic check that the specific values and proper names in a sentence (numbers, dates, addresses, names) appear in the claim text or in that claim's verbatim quotes, and otherwise qualifies the sentence. This needs a design pass and cross-domain tests before it is relied on.

### Minor

- **Verbatim quotes can contain page markdown.** Display could render the link text and drop the URL while keeping storage verbatim.
- **Status reason wording.** With a primary source and other origins, the reason reads "3 sources from separate origins" rather than naming the issuer. This is cosmetic.
- **The model's `origin=` label adds characterisations** ("Amtrak, which operates the station"). Labels are never shown as source text, so this is harmless.
