# Progress log

All commands run from the repo root in the Claude Code cloud container (Linux, JDK 21,
Android SDK installed from dl.google.com: platform 36, build-tools 36.0.0, platform-tools).
No KVM is available in the container, so **no emulator or device was available**; Android
framework behaviour is exercised with Robolectric on the JVM, and instrumented tests are wired
for GitHub Actions (emulator) only.

Sandbox note: Maven Central (`repo.maven.apache.org`) rate-limits this container (HTTP 429/404 with
`retry-after` ≈ 17 h). The build therefore resolves Maven Central artifacts through Google's official
mirror `maven-central.storage-download.googleapis.com` via `~/.gradle/init.d/` and
`robolectricRepoUrl` in `~/.gradle/gradle.properties`. **Neither file is part of the repo**; CI and
developer machines use the normal repositories.

## M1A — Task lifecycle and UI ✅

Completed:
- Screens: **Today** (summary tiles for Needs action / Waiting / Next 24h, overdue, needs action, waiting,
  upcoming reminders, snoozed; one-tap Done with Undo snackbar and Snooze), **Inbox** (review captures,
  Make actionable / Schedule), **Tasks** (filters All/Actionable/Waiting/Paused/Completed/Archived + search
  over title and notes), **Task detail** (edit title/notes/priority, deadline none/date/date-time, status
  actions Done/Make actionable/Resume/Pause/Waiting…/Snooze…/Cancel/Reopen, checklist add/check/reorder/remove,
  reminder schedule editor, activity log), **Quick capture** bottom sheet (type title → 1 tap “Save to Inbox”
  or “Save & remind” with the default preset), **Settings** (default preset/snooze, quiet hours, lock-screen
  privacy, export/import, AI-off indicator).
- First-launch onboarding card; the “Book train ride” example is created only on explicit tap.
- `TaskRepository`: transactional CRUD, state-machine-validated transitions, reopen, snooze (orthogonal to
  status), archive/unarchive/delete (cascade), steps, policy editing, event log with allowlisted metadata
  (no note contents). Every schedule-affecting mutation goes through `ScheduleCoordinator` and bumps the
  policy generation in the same transaction.
- Reminder policy editor: Off / Once / Daily at N times / Every N days, editable presets (Gentle, Daily,
  Persistent = 09:00+18:00), start date, quiet-hours override, follow-device vs fixed zone, live
  “next reminder” preview.
- Snooze dialog shows the exact next eligible reminder before confirming.
- JSON export/import via Storage Access Framework with plaintext warning; validation of format/schema
  version/sizes/ids/enums/timestamps/references; merge by id (newer wins); single transaction (rollback on
  failure); occurrences are never imported (regenerated by the scheduler).
- Room schema **v2** with a real hand-written `MIGRATION_1_2` (v1 schema was committed in M0).
